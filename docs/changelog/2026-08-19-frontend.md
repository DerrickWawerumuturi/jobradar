Built the market analysis, corrected the API contract, split the long scroll
across routes, restyled to a dark editorial system, and added a backend health
indicator.

---

### File
`src/types/jobradar.ts`

### What changed

`RankedJob` was rewritten to match the response the API actually returns, and
every `JobPosting` field is now nullable.

### Why

The declared type claimed `title`, `company` and `location` sat at the root of
`RankedJob`. They do not — the API nests the posting two levels deep, and also
returns a per-job `skills` array the type did not mention at all. Any code
reading `rankedJob.title` would have compiled cleanly and been `undefined` at
runtime.

### How it works

The shape is now `RankedJob.job.job` for the posting and `RankedJob.job.skills`
for its extracted skills, modelled as `JobPosting` and `JobWithSkills`. Every
posting field is `| null` because the backend `Job` model defaults all of them
to `None`.

### Before → After

```
RankedJob.title    →  RankedJob.job.job.title
(undeclared)       →  RankedJob.job.skills
salary: string     →  salary: number | null
```

### Dependencies / relationships

The contract between API and every analysis component. Must be updated before
any component reads a new field.

### Design decisions

The correction unblocked a feature rather than costing one: the per-job `skills`
array was already being returned, so "skills you have / missing" needed no
backend change.

### Learning notes

A boundary type is a claim about someone else's data that the compiler cannot
check. A green type-check proves internal consistency, not that the API agrees.

### File
`src/lib/market.ts`

### What changed

New module holding every display-level transform over `JobRadarAnalysis`.

### Why

Components needed percentages, sorting, priority buckets and skill-set
arithmetic. Inlining that would have duplicated it across sections and blurred
presentation against analysis.

### How it works

`toPercent`, `coveragePercent`, `byDemand`, `significantGaps`, `gapPriority`,
`partitionJobSkills`, `isConstantScore`, `skillKey` / `toSkillKeys`.

### Design decisions

Sorting always operates on a copy and is applied even where the backend sorts,
so a backend change cannot silently reorder a chart.

`coveragePercent` derives from `covered / total` rather than reading `coverage`,
because that ratio is unambiguous regardless of scale.

Thresholds are named exported constants, not literals — they are product
judgments that will be tuned.

### Learning notes

The frontend may *reshape* backend output but must never *recompute* it.
`0.5555` → `55.6%` is presentation; deciding what counts as a gap is analysis.

### File
`src/lib/analysis-store.tsx`

### What changed

New React context provider owning the analysis, upload status and localStorage
persistence.

### Why

The analysis lived in `Hero`'s local state. Splitting the analysis across
routes meant navigation destroyed a result that takes ~45 seconds to produce.

### How it works

Wraps the app in the root layout; exposes `analysis`, `status`, `fileName`,
`save`, `clear`, `hydrated`. Reads localStorage once on mount behind a shape
guard.

### Design decisions

`hydrated` distinguishes "not yet known" from "known to be empty". Without it
the analysis guard runs on first paint and bounces every returning visitor to
the landing page.

Cached values failing the shape guard are deleted, so a response cached from an
older API shape cannot crash the analysis on mount.

State is set before the localStorage write, so a quota failure costs persistence
but never the result.

### Learning notes

State restored from async storage needs three states, not two.

### File
`src/app/analysis/**`, `src/components/Market/Market.tsx` (deleted)

### What changed

The analysis moved from one long scroll to four routes under a shared layout.

### Why

Seven stacked sections made nothing findable, and each answers a distinct
question that deserves its own destination.

### How it works

```
/analysis          overview · coverage
/analysis/skills   demand · my skills · landscape
/analysis/gaps     gaps
/analysis/jobs     matches
```

The layout renders masthead and tab nav and redirects when
`hydrated && !analysis`.

### Design decisions

Nested layouts must use Next's generated `LayoutProps<"/analysis">`; an inline
children type fails typed-route validation in Next 16.

### Learning notes

Route splitting is a state-management problem before it is a routing problem.

### File
`src/components/Market/*`

### What changed

Seven analysis sections plus a shared `SkillBarChart`.

### Why

Steps 2–7 of the analysis spec. `SkillBarChart` exists because demand, my
skills and gaps are all "horizontal bars of skill frequency" — three copies of
the same axis and tooltip config would be three places to change.

### How it works

`SkillBarChart` handles sorting, truncation, the show-all toggle and tooltips.
`SkillGapChart` deliberately does not use it: its rows carry a reason as well as
a magnitude, which a bar chart cannot hold.

`JobMatches` expands rows to show four sub-score meters and skills split
have/missing by set intersection.

`SkillLandscape` plots demand on one axis with filled/hollow points — not the
two-axis scatter specified, because `frequency` and `job_count` are the same
measurement and would draw a straight line.

### Design decisions

One hue per chart; length already encodes magnitude.

`isConstantScore` detects sub-scores identical across all jobs and greys them.
`experience_score` currently is, since no posting has an `experience_level`.
This is self-correcting when the backend improves.

### Learning notes

Presenting a value constant across every row as a differentiator is a way of
lying with true numbers.

### File
`src/lib/backend-health.ts`, `src/components/BackendStatus.tsx`

### What changed

New polling hook and status indicator for the analysis API.

### Why

The failure mode was expensive: click Upload, wait minutes, get "Analysis
failed".

### How it works

Polls `GET /health` every 15s with a 4s `AbortController` timeout and re-checks
on window focus. Network failure, CORS rejection and timeout all collapse to
"offline".

### Design decisions

"Offline" outranks "analyzing" in the displayed state — a backend dying mid-run
is the most useful thing this can report.

Polling initially paused during analysis because `/analyze` blocked the event
loop. Once the API was fixed, the pause was removed rather than left as dead
configuration.

### Learning notes

A status indicator is only worth having if it can report the bad state during
the window the user cares about. That constraint drove a backend fix rather than
a UI compromise.

### File
`src/app/globals.css`, `src/app/layout.tsx`, `src/components/Navbar.tsx`,
`src/components/Hero.tsx`

### What changed

Dark editorial visual system, JetBrains Mono for numerics, rewritten hero copy,
and analysis triggered explicitly rather than as a side effect.

### Why

The UI was undifferentiated white, and the hero claimed "Compare your skillset
to thousands of jobs" while the backend analyzes roughly twenty postings.

### How it works

Tokens rebuilt in `globals.css`: near-black ground, three raised surfaces,
hairline borders, one accent (`#f5532a`) driving `--primary` and the `--chart-*`
ramp — so all five charts repaint from one token change.

### Before → After

Analysis previously fired from a `useEffect` watching
`cv && !open && uploadStatus === 'idle'` — *closing the dialog* started a
multi-minute request. It is now an explicit call from the Upload button.

### Design decisions

`--font-sans` was defined as `var(--font-sans)` — self-referential, resolving to
nothing. Fixed alongside the missing `--font-mono` mapping. Self-referential CSS
custom properties fail silently.

### Learning notes

Effects that start work from incidental state combinations fire unintentionally.
User-initiated work belongs in the interaction that intends it.
